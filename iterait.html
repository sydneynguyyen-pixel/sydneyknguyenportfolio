Context

AI made new designs fast to make, and hard to keep track of.

Designers can now make an interface in seconds with tools like Claude, Cursor, Google Stitch and Lovable. But every prompt makes another version, edits get lost in long chat histories, and a set of prompts that worked once is hard to find and use again.

No way to compare

There's no standard way to put two versions side by side and see what changed.

Lost directions

A direction you dropped three prompts ago is buried somewhere in the chat.

The same prompts, again

A change that worked last week has to be written out again from scratch.

We built iterait at SJHacks 2026, in 24 hours.

Our track asked how we could help digital artists fully realize their creative vision. Our team of four designers kept running into this problem while building our own project with AI tools. So we asked: what if designing with AI came with the version history, reusable pieces and visual structure designers already have in Figma?

My role

I designed the brand, the design system, the home page and the Actions Library.

All four of us came from UX/UI design: three of us designed, and one built the app with AI tools. I designed the logo, the colors and a design system with reusable components, then designed the home page and the Actions Library with it. I also helped write the prompts for the backend in Claude.

Four principles we designed by.

1

Make every version visible.

Every version of a file is saved and shown, so nothing gets lost in a chat.

2

Save changes so you don't rewrite prompts.

A change you like becomes an action you can use again, instead of a prompt you write again.

3

Fit into how designers already work.

It sits next to the AI tools designers already use, rather than replacing them.

4

Work with any AI tool.

Files and actions aren't tied to one tool, so a change made in one can be used in another.

Process

We set up the design system first, then the screens.

We designed and built at the same time, with no handoff. I sketched flows and wireframes, then made the design system before any high-fidelity screens. Once the system existed, the rest of the team had a fixed target to build toward, and that is how we finished something consistent in 24 hours.

Final Product

One place for the design files you make with AI.

iterait collects design files from different AI tools, keeps every version of them, and turns the changes you like into actions you can use again in any tool.

Feature highlight 1

Every version of a file, and what changed in each.

Each file keeps its versions in a sidebar. A changes panel lists what changed in a version, like a darker nav bar or a bigger headline, and clicking a change highlights where it is on the page.

Reflection

What I learned, and what's next.

Designers need AI tools to remember, not only to make more.

The hard part of designing with AI is no longer making a new version. It's knowing what you already tried, why it didn't work, and what to keep. Good design tools have always helped with that, and AI tools don't yet.

Making the design system first is what let us finish.

None of us were trained engineers. Having the system ready early gave the whole team one clear target to build toward for all 24 hours.

The hardest part was splitting changes apart.

An AI tool often makes several changes in one response, so pulling each one out as its own reusable action was tricky. We also had to keep iterait from becoming one more tool to learn, since the point was to make work easier.

What's next.

Test it with professional designers · improve the Actions Library based on how people actually use it · build it as a plugin for Figma and Claude.

Thank you to my teammates Shreya, Michelle and Basmah for making this with me over 24 sleepless hours. I'm so proud we made it to the finals.

Thank you to San José State University, SJHacks and Guildhouse for hosting.
